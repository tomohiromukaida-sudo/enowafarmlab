## 2-4. 「Illustrative IRR」がIRRになっていない

相手方の Scenarios シートの IRR 計算式は以下である。

```
=IF(C14<=0, -100%, RATE(10, 0, -C18, C18 + C14*10))
```

これは「投資額C18が10年後に C18＋EBITDA×10 になる」という**複利成長率（CAGR）**であり、**中間キャッシュフローを一切割り引いていない。**

| ケース | 相手方の表示値 | **正しいIRR** | 乖離 |
| :-- | --: | --: | --: |
| Base（投資33百万、EBITDA 5.282百万×10年） | 10.03% | **9.61%** | +0.4pt（過大） |
| **Upside（投資40百万、EBITDA 32.232百万×10年）** | **24.65%** | **80.36%** | **▲55.7pt（過小）** |

**Baseでは影響が小さいが、Upsideでは55ポイント以上の過小評価になる。**
相手方自身のハードル12%との比較では Base の結論は変わらないが、**Upsideケースの魅力度を大きく損なう誤りである。**

## 2-5. DSCRの分子がCFADSではなくEBITDA

相手方の式：`DSCR = EBITDA / 元利金返済額`

金融実務では **DSCR = CFADS（EBITDA − 維持CAPEX − 税） / 元利金返済額** を用いる。
**相手方はM列でFCF（EBITDA−維持CAPEX）を算出しているにもかかわらず、DSCRにはK列（EBITDA）を使用している。**

- Option A の DSCR 0.86x は、FCFベースなら **0.75x**

**結論（1.2x未達）は変わらないが、数値は相手方に有利な側へ振れている。**

# 3. 統合モデル ― 両者の誤りを最良証拠で置き換える

**相手方の2つの誤りは、方向が逆であるため部分的に相殺している。**

- CAPEX過大（→ NO-GO方向へバイアス）
- 稼働率過大（→ GO方向へバイアス）

**両方を最良証拠に差し替えた場合の結果が、最も信頼できる。**

| **27.4%（福井県 旅館平均）** | Payback 16.6年 / **IRR ▲1.2%** | Payback 21.5年 / **IRR ▲4.2%** |
| **30%（DBJ 分散型標準）** | Payback 15.1年 / **IRR ▲0.1%** | Payback 19.7年 / **IRR ▲3.2%** |
| 45%（相手方前提） | Payback 10.1年 / IRR 5.4% | Payback 13.1年 / IRR 1.7% |

| 稼働率 | CAPEX 30.8百万/室 | CAPEX 40.0百万/室 |

> ## 統合結論
>
> **現実的な稼働率（27〜30%）と現実的なCAPEX（30.8〜40.0百万円/室）の組み合わせでは、IRRはすべて負である。**
> **相手方の「HOLD」判定、当方の「HOLD」判定は、いずれも維持される。**
>
> **ただし重要な差異がある。**
> 相手方の数値（Payback 36.9年、DSCR 1.08x）は**出典のないCAPEXに依存している**ため、そのまま引用すべきではない。
> **実際の不成立理由は「改修費が高いから」ではなく「稼働率が低いから」である。**
> **この違いは、打ち手の設計を変える。**
>
> - CAPEXが原因なら → 補助金・安価な物件・スペック削減が打ち手
> - **稼働率が原因なら → 需要創出・価格設定・販路が打ち手。ハード支援では解決しない**
>
> **後者が正しい。したがって、初期提案Vol2が市に求めているCAPEX支援（物件無償貸与・改修費負担・税免除）は、たとえ全額実現しても本質的な問題を解決しない。**

ただし相手方は Base EBITDA 5.282百万円 に対し「共通Destination Office費、法人税、運転資金、ENOWA本社配賦を含まない」と自ら注記しており、**これらを乗せると Base EBITDA はほぼ消える。**

> **両者の結論は一致する：体験ポートフォリオは「事業」ではなく「検証装置」として位置づけるべきである。**

## 4-3. Water Index の扱い
